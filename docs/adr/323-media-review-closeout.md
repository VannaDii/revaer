# Media review closeout

- Status: Accepted
- Date: 2026-07-21
- Context:
  - PR review for the media transcoding work identified gaps across target constraints, execution, verification, fail-closed behavior, capability validation, and CI/Sonar strictness.
  - ADR 317 intentionally described the service as incomplete until desired targets, worker execution, and verification covered video, audio, HDR, chapters, metadata, stream-kind, and codec-support behavior with acceptance evidence.
  - The repository requires normalized persistence, stored-procedure runtime access, fail-closed behavior, no source/test exclusions that hide authored code, and task records for implementation changes.
- Decision:
  - Model desired video constraints as normalized target and job-snapshot fields for profile, level, bitrate, color primaries, transfer, colorspace, and HDR format.
  - Drive FFmpeg video arguments from immutable target snapshots and verify source, candidate, and final outputs against normalized profile, level, bitrate tolerance, HDR/color tags, and HDR10 side-data.
  - Model desired audio bitrate and sample-rate constraints, emit matching FFmpeg arguments, preserve complete probe sample-rate data, and verify source, candidate, and final outputs fail-closed on missing or mismatched values.
  - Reject unsupported desired target stream kinds for attachment, chapter, and data rows until complete desired-state schemas and verification contracts exist.
  - Reject unsupported HDR format labels in core validation and database constraints, keeping the accepted value set intentionally small and versioned.
  - Reject metadata rewrite command construction with a stable preflight error until normalized desired metadata rows and verification are implemented.
  - Preserve chapters by default with shared FFmpeg argv construction and verify normalized chapter timing plus metadata before and after replacement.
  - Extend graph diff and planning for stream language, title, and disposition mismatches, producing label and disposition rewrite operations.
  - Fail closed when constrained target streams cannot be mapped to inspected streams during preflight or verification.
  - Require every advertised media capability codec to have explicit codec support rows with at least one supported direction.
  - Keep Sonar and CI criteria strict; do not relax scanner scope, warnings, coverage reporting, dependency checks, or quality gates to make this work pass.
- Consequences:
  - Queued jobs snapshot immutable desired media intent before worker execution, so later catalog edits cannot change the work being verified.
  - Candidate and final verification now rejects graph-compatible but constraint-incomplete media before replacement, or rolls back replacement when final verification fails.
  - Unsupported stream kinds, HDR labels, metadata rewrites, and unmapped constrained streams fail before destructive execution.
  - The remaining metadata rewrite and opaque data-stream contracts stay explicit future work instead of partially supported behavior.

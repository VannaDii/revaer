# Media Transcoding Foundation And PR 31 Implementation Record

- Status: Accepted, implementation incomplete
- Date: 2026-07-20

## Context

- PR 31 introduces the first production-shaped media inspection, planning, execution, persistence, API, UI, discovery, observability, and fixture-validation surfaces.
- Iterative review fixes produced many narrow task records that repeated the same motivation, tests, and rollback posture.
- Green CI does not prove that the service satisfies the full media-transcoding contract. Two unresolved implementation gaps remain, including measured audio semantics and completion of the remaining desired-target graph.
- This record consolidates the media decisions previously split across ADRs 318-321, 323-343, 348, 350, 354, and 356. It deliberately replaces all "closeout" claims with the current verified status.

## Decisions

### Architecture and persistence

- Keep media domain types and deterministic planning in `revaer-media-core`, external tool execution and probing in `revaer-media-runtime`, stored-procedure persistence in `revaer-data`, and bootstrap/orchestration in `revaer-app`.
- Persist profiles, compatibility catalogs, capability runs, jobs, diagnostics, plan snapshots, and audit facts through normalized tables and stored procedures.
- Snapshot enqueue-time profile intent into jobs so later profile edits do not silently change claimed work.
- Persist verification strictness, duration tolerance, and selected mux, decode, keyframe, and playback checks in each versioned policy. Snapshot those fields into every job so catalog replacement cannot change queued work.
- Persist immutable desired-target versions as normalized profile, container, ordered stream, and audio-shape rows. Profiles pin an exact version and jobs copy the complete stream graph at enqueue time.
- Keep desired targets, compatibility admission, and operational policy separate. The target owns final stream order and per-stream output shape; policy independently owns unmatched-source behavior.
- Validate profile catalog references, source/output path bounds, and cross-profile overlap in the database as well as at service boundaries.
- Reject overlap across discovery, output, and protected roots, including concurrent profile updates.

### Inspection, planning, and execution safeguards

- Treat probed stream indexes as runtime correlation values only. Persist target stream keys plus semantic kind, role, and language selectors, then match deterministically at planning time.
- Compile desired streams in declared target order with independent output identities and explicit source binding keys. Distinct binding keys consume one source match each; a shared binding key intentionally fans one source out to multiple outputs. Reject missing required rows, skip missing optional rows, and apply explicit remove, preserve, or reject behavior only to source streams not selected by any binding.
- Validate duplicate stream IDs, missing desired streams, stream-kind mismatches, operation-list shape, container-operation targets, audio channel shape, subtitle commentary selection, and default subtitle disposition before execution.
- Preserve source order where policy does not explicitly reorder, and represent no-op plans explicitly rather than invoking a transcode unnecessarily.
- Keep destructive replacement gated behind dry-run policy, capability checks, plan validation, candidate verification, and path containment.
- Enforce strictness semantics at the API, database, and worker boundaries: strict selects mux, full-stream decode, midpoint keyframe, and playback checks; fast cannot select decode, keyframe, or playback checks. Run selected playback smoke checks through FFplay with closed stdin and dummy SDL drivers so container execution remains noninteractive and device independent.
- Address output channel layouts by the portable typed audio-stream option (`-channel_layout:a:N`), preserving deterministic desired-graph mapping across supported FFmpeg releases.
- Prepare replacement stages and recovery copies under a managed transaction directory on the canonical source filesystem. Sync staged data, recovery data, manifests, the source, and affected directories; reject direct replacement through the generic filesystem executor.
- Record prepared, committed, and verified transaction phases. Roll back failed final verification immediately, conservatively recover uncertain committed work at startup, preserve verified replacements during interrupted cleanup, and pause job claiming while startup recovery is incomplete.
- Persist monotonic cancellation request and acknowledgement generations for every job. Queued cancellation terminates immediately; claimed work remains worker-owned until the worker observes the generation, stops and reaps any active FFmpeg or verifier child, discards an uncommitted prepared replacement or rolls back a committed replacement, removes transient workspace output, persists cancellation evidence, and acknowledges the exact generation.
- Poll durable worker control at bounded intervals during active child execution and at every preflight, inspection, verification, preparation, commit, and final-verification boundary. Complete through one atomic stored procedure that converts a pending cancellation into the terminal cancelled state instead of allowing completion to win the race.
- Install Trunk through one exact-version, published-lockfile recipe so every UI validation shard reaches the application tests with an identical tool dependency graph.
- Emit durable job events and bounded-cardinality metrics for discovery, planning, execution, verification, replacement, and terminal outcomes.

### Discovery, API, UI, and configuration

- Support scheduled recovery scans and recursive native filesystem events through an injected watcher boundary. Reconcile enabled profile associations at runtime and debounce each `(profile, path)` independently before fingerprinting.
- Hash stable files with SHA-256 after canonical containment checks. Atomically persist `(size, modification time, hash)` and create the inherited-dry-run job in one stored procedure so duplicate native events, scheduled scans, failed enqueues, and process restarts cannot lose or duplicate a file version.
- Validate schedule intervals, inherit profile dry-run state when discovery enqueues work, and recognize the complete documented audio/video container extension set, including WebM, MPEG-TS, and M4A.
- Stream adjacent directory entries during sidecar discovery and retain only names matching the normalized media stem, a supported extension, and a documented language/role shape. Enforce the reviewed per-source budgets of 4,096 examined entries, 64 logical sidecars, and 256 MiB across retained physical files. Resolve VobSub `.idx` files through a targeted `.sub` companion lookup, count both files against the byte budget, sort the bounded result deterministically, and reject matching non-UTF-8, symlink, non-regular, incomplete, or normalized-identity-ambiguous candidates fail-closed.
- Bound each media inspection to 30 seconds, 65 process invocations, 16 MiB stdout and 1 MiB stderr per invocation, 32 MiB aggregate process output, and 64 logical sidecars. FFprobe accepts one independent input per invocation, so inspection uses one rich source probe plus at most one probe per logical sidecar instead of constructing an unsafe synthetic batch. A paired VobSub `.idx`/`.sub` inventory consumes one logical sidecar and one probe while both physical files retain separate identity checks and contribute to the discovered-byte total.
- Inject process execution, sidecar discovery, and cancellation. The system process adapter closes stdin, drains bounded stdout and stderr concurrently, polls the request cancellation signal and remaining deadline, terminates the Unix process group, reaps the child, and fails closed when cleanup cannot be proven. The service defensively rechecks collaborator output and invocation limits rather than trusting an injected implementation to enforce its request.
- Snapshot every source and physical sidecar as a regular non-symlink file before probing and verify the complete set after each invocation and before returning. Unix identity includes device, inode, length, modification time, and change time, so replacement and same-length in-place mutation fail closed. Reject inconsistent companion shapes, duplicate physical paths, mismatched discovered byte counts, malformed output, duplicate stream or chapter identifiers, and sidecars without exactly one matching subtitle stream.
- Keep API DTOs, OpenAPI, generated test clients, CLI surfaces, and the media UI synchronized with persisted configuration and job diagnostics.
- Expose complete desired-target create/list DTOs and a separate profile pin endpoint. Target creation and all stream-row inserts commit atomically.
- Decouple UI refresh from diagnostics rendering so polling does not erase the last useful failure state.
- Export and import typed configuration through a strict `format_version: 1` / `kind: revaer.media.profile_bundle` contract. Bundles carry metadata, profiles, compatibility catalogs, immutable desired targets with ordered streams, and versioned verification policies.
- Omit local roots by default and report each unresolved root with a non-blocking JSON Pointer issue. Persist unresolved profiles in a normalized disabled-draft table that cannot be discovered or enqueued; reapplying a mapped bundle atomically creates the forced-dry-run profile and removes its draft. Same-instance imports reuse existing local roots, and later exports include unresolved drafts.

### Fixture and CI evidence

- Maintain deterministic media fixtures covering compatible, incompatible, reordered, audio-channel, subtitle, metadata, corrupted, and failure paths.
- Generate fixtures through `just`, verify checksums and expected probe facts, and execute real conversion tests with the same tools shipped in the runtime image.
- Run media conversion fixtures as an independent PR job, publish the conversion report, and avoid the shared multi-gigabyte Cargo cache for that job.
- Keep fixture caches keyed by the manifest, generation scripts, and media-tool versions.
- Remove generated test media after validation; committed fixture manifests and small source fixtures remain the reproducible inputs.
- Keep Sonar's repository scope, analyzers, SCM context, Rust LCOV import, native compile database, and quality-gate wait strict. Analyze every authored tracked top-level entry and hidden file as main code without source, test, issue, coverage, duplication, dependency, JavaScript, or binary suffix exclusions. Point `sonar.tests` only at an empty committed sentinel so Sonar's automatic path heuristic cannot exempt documentation or test-named files from secrets analysis. Enable analyzer cache support for cross-file symbolic execution, force complete SCM blame reload, require real LCOV source and line-data records at both workflow boundaries, retain the complete submitted scanner report, and require a post-scan API gate that proves positive coverage publication, non-ignored quality-gate evaluation, and zero unresolved new-code issues or hotspots.

## Verified Scope

- The current implementation has stored-procedure-backed profile/job/catalog persistence, immutable normalized desired-target graphs, deterministic semantic target compilation, runtime capability detection, FFmpeg/FFprobe command construction, discovery scheduling, API/UI surfaces, metrics, and real media fixture coverage.
- Destructive replacement now stages on the source filesystem, retains and syncs a recoverable original, uses same-filesystem rename, validates the final graph, rolls back mismatches, and recovers interrupted transactions before the worker claims new jobs.
- Production inspection now requests streams, format, and chapters in one ffprobe invocation; normalizes container duration/start/size/bitrate/metadata, chapter timelines, data streams, technical video and color/HDR properties, arbitrary stream metadata, and side-data descriptors; and retains the existing planning graph as a stable projection.
- Production inspection also invokes an injected filesystem sidecar discoverer for every source. It recognizes the documented language/role filename forms and `srt`, `ass`, `vtt`, `sup`, `sub`, and paired VobSub `idx`/`sub` formats; normalizes common language aliases and semantic roles; ignores unrelated neighbors; rejects duplicate normalized identities and incomplete VobSub pairs; FFprobe-validates that every discovered file contains exactly one subtitle stream matching its declared format; and retains the deterministic inventory in the complete inspection report. Image-based formats are marked explicitly so later target compilation cannot silently select an OCR path, and an image subtitle masquerading as standalone text `.sub` is rejected.
- Immutable desired subtitle rows now persist `embedded`, `sidecar`, `both`, or `none` placement plus `preserve`, `remove`, or `fail` image-subtitle behavior. API, stored-procedure, relational-shape, and job-snapshot validation reject invalid values, subtitle-only fields on other stream kinds, and the audio-only descriptive-audio role on subtitle rows. Sidecar-aware compilation consumes embedded streams before discovered sidecars, applies the same unmatched `remove`, `preserve`, or `reject` policy to both source classes, refuses OCR-dependent image conversion, derives separate managed-workspace and final source-adjacent paths, and rejects unsupported or colliding output formats before execution.
- Runtime planning and execution now support external subtitle embedding, embedded subtitle extraction, lossless sidecar copy, supported text subtitle conversion, image-subtitle preservation without OCR, and paired VobSub artifacts. Preflight capacity accounts for the container and every unique discovered sidecar or companion file. The source media plus every sidecar create, replace, and remove operation is one durable recovery unit: each item is staged and synced on the source filesystem, commit progress is persisted after every rename or removal, final graph and sidecar state are verified before recovery data is discarded, and any failed or interrupted final verification restores all originals and removes newly created artifacts.
- Source chapter preservation is now explicit for primary media outputs. FFmpeg command construction emits `-map_chapters 0`, worker preflight carries the inspected source chapter timeline, and source, candidate, and final full inspections verify that timeline before a replacement can complete. Desired target stream kinds still fail closed for authored chapter edits and attachments. Full inspection still retains those facts, but API requests, YAML imports, core compilation, and database constraints reject target rows whose payload, timeline, metadata, execution, and verification semantics are not yet implemented. Arbitrary metadata rewrite operations also fail closed at command construction with a stable preflight error until the target schema and verification contract exist.
- Stream language, title, and disposition drift is now represented in core diffing, compliance scoring, and planning. Metadata-only stream changes produce `LabelRewrite`, disposition-only stream changes produce `DispositionRewrite`, and the desired-graph FFmpeg builder emits the target stream tags and disposition flags during the mutating pass.
- Desired target HDR format labels now fail closed outside the implemented `hdr10` subset. The core compiler and database append path reject unsupported labels, and catalog/job snapshot constraints prevent unsupported HDR desired state from being persisted as if it had a verification contract.
- Desired target audio rows now persist `dialog-normalized` loudness policy and `preserve` or `speech` dynamic-range policy through API DTOs, stored procedures, immutable target rows, YAML import/export, and job snapshots. Runtime command construction forces concrete audio encoding when either policy requires filtering, applies `loudnorm` for dialog normalization, and applies an audio compressor for speech dynamic range. Candidate and final audio verification now measure policy-constrained output with FFmpeg `ebur128`, require dialog-normalized integrated loudness in `-17.0..=-15.0` LUFS with true peak at or below `-1.0` dBFS, and require speech loudness range at or below `12.0` LU.
- Desired container selection is operational across target compilation, graph diffing, compliance scoring, planning, execution, and post-replacement verification. Common filename aliases normalize to canonical FFmpeg muxer names, a mismatch produces a remux operation, preflight rejects a muxer absent from the captured capability snapshot, FFmpeg receives an explicit `-f` argument while retaining the specification-required in-place source pathname, and final FFprobe inspection must report the selected container before replacement is accepted.
- Candidate replacement now persists separate duration-delta and policy-selected mux-structure, full-stream decode/corruption, keyframe-seek, and FFplay playback-smoke results. Any failed check quarantines the candidate before transaction preparation, and a regression proves a probeable truncated candidate cannot replace the original.
- Versioned policy rows expose verification strictness and check selection through the API, OpenAPI contract, generated client, and operator UI. Jobs retain the enqueue-time policy snapshot even after the same catalog version is replaced.
- Media API stream DTOs now reuse the shared desired-target stream model, and OpenAPI job record schemas share one append/response/list schema builder so PR Sonar duplication is fixed in code without coverage, duplication, or issue exclusions.
- Versioned YAML exchange now round-trips the complete implemented relational configuration graph. Import rejects unknown fields, foreign kinds, unsupported versions, duplicate catalog identities, conflicting immutable versions, malformed policy/target rows, and missing references before opening its write transaction. Catalog writes, desired-stream creation, profile creation, desired-target pinning, draft persistence, and draft resolution commit atomically.
- Completed-job and failed-diagnostic retention are independently configurable by enabled state, age or retained-count mode, and bounded limit. One atomic stored procedure deletes eligible completed jobs, prunes bulky failed diagnostics without deleting the job shell, and preserves compact audit facts independently of the deleted job row. An injected hourly runtime supplies the clock and repository and starts from bootstrap.
- Watcher-enabled profiles now install recursive OS-native subscriptions through `notify` 8.2, rebase canonical event paths to configured root aliases, debounce per profile/path, reject canonical path escapes, fingerprint only stable files, and share durable atomic fingerprint claims with scheduled scans. Duplicate events and unchanged restart scans do not enqueue; content, size, or modification-time changes do.
- The exact-tree `just ci` gate passes locally, including the 90% per-crate line-coverage floor and LCOV generation, without relaxing any threshold or scope. All 104 browser/API end-to-end tests also pass through `just ui-e2e`.
- Remote PR jobs execute media fixtures, feature combinations, coverage, release builds, architecture image builds, manifest/Helm validation, CodeQL, Trivy, and Sonar.

## Open Implementation Gaps

The service is not complete until both broader implementation gaps below are closed with acceptance-test evidence. All current GitHub review threads are resolved against their requested scope, but that thread state does not establish production completeness beyond the implemented contracts:

1. Complete the remaining stream constraints and verify the full immutable graph rather than the now-operational container, generic stream identity, stream language/title/disposition, audio channel shape, audio bitrate/sample-rate constraints, measured `dialog-normalized`/`speech` audio policy subset, subtitle-placement, video-constraint execution, and video-constraint verification subset. Candidate and final verification now gate constrained video outputs against inspected profile, normalized level metadata, bitrate tolerance, HDR10 color signaling, and required HDR10 mastering-display/content-light side-data descriptors, and constrained audio outputs against inspected bitrate tolerance, exact sample-rate constraints, dialog-normalized LUFS/true-peak measurements, and speech loudness-range measurements. Constraint mapping now fails closed when authored target rows cannot bind to compiled desired streams. Unsupported HDR format labels now fail closed instead of persisting an unverified desired state. Broader loudness policies, richer HDR side-data value semantics, codec-specific level boundary semantics beyond common FFmpeg/FFprobe dotted and integer forms, and other technical-property semantics remain open.
2. Complete desired-state compilation and verification for authored chapter edits, attachments, arbitrary metadata, detailed HDR/color enforcement, and other technical properties retained by full inspection. Source chapter preservation is now explicit in FFmpeg argv and verified against source/candidate/final full inspection. Chapter edit and attachment desired rows still fail closed instead of being accepted without a complete contract, and metadata rewrite command construction now rejects unsupported arbitrary metadata operations instead of stripping tags. Container, stream graph, stream language/title/disposition drift, source-adjacent sidecar placement, and source chapter timeline preservation are now checked, while immutable profile-selected duration, mux, decode/corruption, keyframe, and FFplay checks gate candidate safety within their implemented scopes.

## Alternatives Considered

- Treating green CI or a passing Sonar gate as implementation completion was rejected because neither exercises the missing runtime contracts above.
- Resolving review threads without implementation evidence was rejected.
- Keeping one ADR per small review follow-up was rejected because it obscured the service-level design and produced contradictory closeout claims.
- Moving runtime SQL into application code was rejected; stored procedures remain mandatory.
- Hand-rolling media parsing or conversion was rejected in favor of FFmpeg/FFprobe with normalized, testable adapters.

## Task Record

- Motivation:

- Design notes:
  - The managed-workspace stack layer adds deterministic reserve/capacity evaluation, job-scoped input/output/diagnostic layouts, terminal-state cleanup, and a bounded partial-failure-tolerant retention sweep while leaving persisted scheduling and worker wiring to the later orchestration layer. The implementation separates lifecycle models, capacity policy, filesystem operations, janitor behavior, and tests so each production module remains cohesive and below the Rust file-size target.
  - The runtime-capability stack layer exposes only deterministic FFmpeg capability models and an injected detector. Its concrete process adapter fails closed off Unix and enforces a per-probe deadline, bounded stdout and stderr capture, closed stdin, process-group termination, and child reaping before any later inspection or execution surface is introduced.
  - The bounded-inspection stack layer separates orchestration, public models, FFprobe decoding, normalization, and cancellable system-process execution. It preserves the complete technical report and planning graph while sorting streams by identifier, chapters by timeline and identifier, and sidecars by path. This layer consumes the bounded sidecar-discovery contract and does not wire job persistence, worker scheduling, or telemetry.
  - Runtime collaborators are injected; bootstrap owns concrete process, filesystem, clock, watcher, database, and telemetry implementations.
  - Planning is deterministic and side-effect free; execution consumes a validated snapshot.
  - Runtime planning consumes the bounded inspector's `MediaInspection.graph`, selects the planner's least-cost validated candidate, and retains explicit source and desired-output identities on every stream-scoped operation. Sidecar extraction remains source-scoped, while sidecar embedding remains desired-output-scoped.
  - Database invariants are enforced in migrations and stored procedures, not only in API validation.
  - Desired-target versions become immutable when assigned to a profile or snapshotted by a job. New desired output behavior requires a new version.
  - Replacement transactions are source-root anchored and dependency injected. Generic execution cannot bypass their durable prepare, commit, verify, rollback, finalize, and startup-recovery phases.
  - Primary media and source-adjacent subtitle mutations share one recoverable transaction manifest. This provides deterministic rollback and crash recovery across a multi-file publication even though filesystems do not expose a single atomic rename spanning multiple destination paths.

- Dependency rationale:
  - `rustix` 1.1.4 supplies safe Unix descriptor flag and process-group signal APIs for bounded native tool execution. `std::process` does not provide process-group termination or portable nonblocking pipe configuration; invoking a shell timeout utility would add an untracked runtime dependency and would not provide bounded output capture.
  - `notify` supplies maintained OS-native filesystem subscriptions instead of a polling loop or bespoke platform FFI. Its `CC0-1.0` public-domain dedication is named explicitly in the cargo-deny allowlist, without a crate-specific exception or advisory ignore.
  - Core media behavior uses shipped FFmpeg/FFprobe. `notify` 8.2.0 is added as the maintained cross-platform abstraction over Linux inotify, macOS FSEvents, Windows directory-change notifications, and supported BSD backends; hand-written platform watchers would add substantially more unsafe and platform-specific failure surface. Version 7 was rejected because it resolves the unmaintained `instant` crate covered by RUSTSEC-2024-0384. The current Windows backend adds the 0.60/0.53 target-support line alongside dependencies still pinned to 0.52/0.59; exact cargo-deny duplicate tolerances expire on 2026-10-01 and must be removed sooner if TLS and password-input dependencies converge. `sha2` 0.10 is promoted from an existing transitive/direct workspace use to an explicit app dependency for portable SHA-256 source identities. Existing `anyhow` and `tempfile` dev dependencies cover fallible temporary-filesystem tests.
  - Policy-selected playback uses the FFplay 8.0.1 Alpine subpackage from the same FFmpeg source release. Its exact package version, license, and SHA-256 are recorded in the runtime SPDX inventory; no Rust dependency is added.
  - Sidecar discovery, content validation, planning, and recoverable publication use `std`, existing FFmpeg/FFprobe process boundaries, and the existing test-only `tempfile` dependency. No production dependency was added.
  - Bounded inspection reuses the workspace `revaer-media-core`, `serde`, `serde_json`, `thiserror`, and `rustix` dependencies. `revaer-media-core` supplies the canonical graph and normalization contract; `serde_json` decodes FFprobe's structured output; `rustix` supplies safe Unix process-group termination.
